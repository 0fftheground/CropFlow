# 植保方向开发排期

> 本文档只保留植保方向闭环落地所需的核心排期信息。  
> 当前排期起点按 2026-05-11 这一周计算。  
> 技术栈已确认：后端 `Python + FastAPI`，数据库 `PostgreSQL`，部署方式 `Docker`，前端技术栈由前端负责人确定。

---

## 1. 目标

在 2026-08-07 前完成植保方向主要农事的闭环落地、预发布验收和正式演示准备。

植保范围包括：

```text
1. 药剂入库
2. 土壤封闭除草
3. 茎叶除草药前调查、防治、药后调查和补防判断
4. 封行病虫调查与防治
5. 突发病虫调查与防治
6. 齐穗病虫调查与防治
7. 破口病虫调查与防治
8. 植保服务效果评估
```

## 2. 必要前提

植保不是孤立开发，必须先具备以下最小模块能力：

```text
1. Plan Module：支持种植计划创建、查询、关键字段更新
2. Stage Orchestrator：支持气象输入、生育期预测刷新和阶段变化处理
3. Task Module：支持农事日历刷新、调查日期维护、预备农事项管理、正式任务生成
4. Material & Inventory Module：支持药剂入库和可用药剂查询
5. Execution Module：支持植保执行步骤、执行记录和状态同步
6. Evaluation & Feedback Module：支持执行后反馈、药后调查和服务效果评价
7. Review Module：支持补防、异常结果的人工复核
```

## 3. 工作主线

本排期只按 5 条主线推进：

| 主线 | 要做什么 |
|---|---|
| 上游支撑 | PlantingPlan、气象数据、生育期、农事日历、CalendarItem、TaskDueCheckJob |
| 后端模块 | Plan / Stage / Task / Inventory / Execution / Feedback / Review 最小能力 |
| 植保接入 | 植保算法适配、规则、DTO、映射、各 workflow 接入 |
| 前端页面 | 页面清单、原型、mock 页面、联调页面、演示页面 |
| 其他方向准备 | 农事日历 / 生育期、施肥、灌溉、遥感监测的非代码接入包 |

## 8. 验收标准

到排期结束时，至少满足：

```text
1. 植保主要 workflow 已全部接入。
2. 上游链路 PlantingPlan -> WeatherUpdated -> Stage -> CalendarItem -> TaskDueCheckJob 稳定可用。
3. 后端模块最小能力齐备：Plan / Stage / Task / Inventory / Execution / Feedback / Review。
4. 植保算法适配、规则、DTO、映射、fixtures、integration tests 齐备。
5. 前端页面能完整演示计划创建、调查、防治、反馈、复核、服务效果评估。
6. 有可重复部署的预发布或演示环境。
7. 已完成至少一次完整彩排，并准备回退方案。
```

## 9. 当前主要阻塞项

| 阻塞项 | 责任人 | 风险 |
|---|---|---|
| 植保全方向 workflow 清单未冻结 | 产品 / 架构负责人、植保 | 无法判断是否覆盖全部农事 |
| 调查字段、方案字段、药后调查字段未收敛 | 植保 | 无法稳定 DTO 和映射 |
| 核心对象骨架和 API contract 未冻结 | 核心后端 | 前后端和方向无法同步推进 |
| 气象数据、PlantingPlan、Stage、CalendarItem、TaskDueCheckJob 上游链路未落地 | 核心后端、农事日历 / 生育期 | 植保主线无法稳定生成正式任务 |
| 预发布环境负责人或部署分工未明确 | 产品 / 架构负责人、核心后端 | 上线前集中暴露环境和部署问题 |
| 演示数据、演示账号和回退方案未提前准备 | 前端、核心后端、产品 / 架构负责人 | 现场演示风险过高 |

## 10. 使用原则

```text
1. 这是一份植保闭环落地排期，不是完整平台建设排期。
2. 先保植保全方向闭环，再考虑其他方向正式接入。
3. 先保模块最小能力，再考虑平台化和通用化。
4. 任一阶段关键交付未完成，不建议进入下一阶段。
5. 新增需求如果不属于当前植保范围，默认进入后续阶段。
```
