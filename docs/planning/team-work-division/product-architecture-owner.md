# 产品 / 架构负责人

> 本文档从团队分工总览中拆出，用于单独说明产品 / 架构负责人的职责、关注点和近期交付物。

负责人：All。

## 当前阶段说明

当前项目仍处于核心对象、ER 图、表结构草案和 API contract 收敛阶段。

因此本角色当前任务以范围冻结、规则拍板、文档收口和跨方向对齐为主，而不是直接要求各方向进入大规模代码实现。

## 主要职责

```text
1. 维护领域口径、核心对象和模块边界。
2. 确认业务规则、流程分支和接口优先级。
3. 判断新增需求是否进入 MVP。
4. Review 文档、表结构、API contract 和 PR 是否违反核心设计。
5. 组织每个方向补齐算法接口、OperationPlan 映射、执行反馈和评价规则。
```

## 需要重点确认

```text
1. 每个农事项是否需要生成 CalendarItem、FarmingTask、OperationPlan。
2. 哪些算法结果可以自动转任务，哪些必须人工确认。
3. 哪些执行结果会触发 Feedback、ReviewRequest 或后续任务。
4. 哪些字段需要结构化，哪些第一版先放 JSON。
5. 第一条垂直闭环的验收标准。
```

## 当前阶段非代码任务

```text
1. 冻结 MVP 范围和不做范围：
   明确哪些需求进入当前版本，哪些进入后续阶段。
2. 冻结第一条垂直闭环：
   明确从计划创建到反馈/复核的最小链路，避免各方向各自扩张范围。
3. 确认核心对象和模块边界：
   审核核心后端的对象草案，防止出现语义重复或边界错位。
4. 确认业务流程和分支规则：
   对各方向提交的 taskSubtype、触发规则表、依赖关系表、复核规则做统一拍板。
5. 冻结 API contract 优先级：
   明确哪些接口和字段是 P1 必须冻结的，哪些先留待后续。
6. 冻结第一条闭环验收标准：
   明确前后端和各方向如何判断 P1/P2 是否可进入下一阶段。
7. 收口待决事项：
   统一记录拍板结果，并回写 docs/model、docs/workflow、docs/planning 中的核心文档。
```

## 当前阶段完成标准

```text
1. 不要求当前直接交付代码，但必须给出明确的范围、边界、优先级和验收标准。
2. 所有跨方向冲突、歧义和待决事项必须形成明确结论，不能停留在口头约定。
3. 核心对象、关键流程、关键后台任务和第一条闭环边界必须有统一口径。
4. 各方向提交物的 Review 结论必须可追溯，并能指导后续实现。
```
