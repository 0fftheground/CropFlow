# 任务 / 流程 FDE 通用输出模板

> 用途：作为 FDE 采访业务、算法、前后端、实施或运营时的标准输出模板。  
> 目标：让一份文档足够支撑需求澄清、后端建模、流程编排、接口设计、前端录入、联调排错和测试场景设计。  
> 适用范围：不仅适用于植保，也适用于农业其他方向，甚至可复用到非农业行业的任务型、流程型、规则型系统。

## 1. 设计目标

这份模板不是领域专属模板，而是“可开发结果模板”。

它解决的问题是：

```text
1. 业务访谈结果经常只停留在流程描述，不能直接支撑开发。
2. 文档经常只写正常链路，不写失败、分支、人工判断和对象映射。
3. 不同方向各写各的，导致后端、前端和测试无法共用一套阅读方式。
```

因此模板只固定“开发最需要的信息结构”，不绑定某个行业。

## 2. 哪些信息最能加速开发

无论什么行业、什么方向，下面这些内容如果在采访阶段先问清，后续开发都会明显更快：

| 优先级 | 内容 | 为什么重要 |
|---|---|---|
| P0 | 这条流程的业务目标和闭环结束条件 | 决定系统什么时候开始、什么时候结束 |
| P0 | 触发事件、前置条件、阻断条件 | 决定什么时候创建、重算、跳过或报错 |
| P0 | 输入字段来源表 | 决定数据来自已有对象、外部系统还是人工录入 |
| P0 | 结果分支表 | 决定系统进入无动作、下一步、人工确认或正式执行 |
| P0 | 下游对象映射 | 决定代码落在哪个模块、哪些 API 要变 |
| P0 | 人工判断规则 | 决定审核页、人工任务、决策动作结构 |
| P1 | 录入字段结构 | 决定前端表单和后端 payload 结构 |
| P1 | 执行 / 方案对象最小字段 | 决定正式执行前后的对象模型 |
| P1 | 重算 / 覆盖 / 幂等规则 | 决定 update、invalidate 还是 create |
| P1 | 失败兜底和缺数据处理 | 决定通知、重试、人工介入和排错方式 |
| P2 | 页面操作建议 | 决定前端联调成本 |
| P2 | 测试场景 | 决定回归验证能否快速落地 |

## 3. 最小可开发集

如果只是想让后端或平台团队尽快开工，至少要把下面内容写完整：

```text
1. 流程名称和建议标识
2. 业务目标与闭环结束条件
3. 触发时机、前置条件、阻断条件
4. 输入字段来源表
5. 外部接口 / 规则 / 人工判断入口
6. 结果分支表
7. 下游对象映射表
8. 录入字段
9. 人工判断规则
10. 至少 3 个端到端测试场景
```

# 模板正文

> 建议一份文档只描述一个“可独立开发或联调的任务 / 子流程 / 业务闭环片段”。

## A. 基本信息

```md
# <任务 / 流程名称>

## 1. 基本信息

- 业务名称：
- 建议流程标识：
- 所属业务线 / 模块：
- 当前阶段：
  - P0 调研 / P1 可开发 / P2 联调 / P3 上线收口
- 适用范围：
- 不适用范围：
- 关联角色：
  - 发起方：
  - 执行方：
  - 审核方：
  - 结果使用方：
```

### 填写说明

```text
1. 不要求一开始就冻结系统 id，但要给出一个可追踪的建议标识。
2. “适用范围 / 不适用范围” 要尽早写，避免错误泛化。
3. 如果存在多角色协作，一定要分清谁发起、谁执行、谁确认、谁消费结果。
```

## B. 业务目标与闭环定义

```md
## 2. 业务目标

- 这条流程解决什么问题：
- 系统为什么需要感知它：
- 最终希望输出什么结果：

## 3. 闭环结束条件

- 什么情况下视为完成：
- 什么情况下转入下一流程：
- 什么情况下仅记录，不继续推进：
- 什么情况下转人工：
```

### 填写说明

```text
1. 如果“什么时候算结束”不清楚，后续一定会在状态流转上返工。
2. 一定要区分：完成、跳过、失败、转人工、转下一步。
```

## C. 触发与重算规则

```md
## 4. 触发规则

- 触发来源：
  - 计划创建 / 数据更新 / 任务到期 / 人工录入 / 外部回调 / 定时任务 / 手工操作
- 具体触发事件：
- 前置条件：
- 阻断条件：
- 是否允许重算：
  - 是 / 否
- 重算触发条件：
- 重算后旧对象如何处理：
  - 覆盖 / 失效 / 新增新对象 / 仅记录事件
- 幂等建议：
```

### 填写说明

```text
1. 这里要回答“同一件事再发生一次时，系统该怎么办”。
2. 如果推荐日期、判断结果、输入参数变化会影响旧结果，也必须写清。
```

```text
1. 这是最重要的表之一。
2. 不要只写“需要上下文数据”，要写清范围、粒度、缺失时动作和是否必须连续。
```

## O. 采访完成标准

当下面这些内容都能回答时，基本可认为这条流程已经达到“可开发”状态：

```text
1. 触发时机、前置条件、阻断条件明确。
2. 输入字段和来源明确。
3. 外部接口 / 规则 / 人工判断入口明确。
4. 结果分支明确。
5. 下游对象映射明确。
6. 录入字段明确。
7. 人工判断动作明确。
8. 失败兜底明确。
9. 至少 3 个测试场景明确。
10. 未冻结口径已显式列为待决问题。
```
